# FIDO2 hmac-secret slots (v0.3.0) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A YubiKey's FIDO2 application can hold a vault slot (`init --fido2`, `slot add --fido2`) that opens with the key's PIN and a touch on Linux, macOS and Windows alike, so a YubiKey works on a Mac without Input Monitoring.

**Architecture:** A new slot blob (YubiKey magic `TSYK`, version 3) and KEK derivation sit beside the OTP ones in `TswapCore/Keyring`. A FIDO2 service (`IFido2Service`) owns the texts, the PIN policy and the YubiKey check, over a device seam (`IFido2Keys`) with three implementations: Yubico's SDK (Linux, macOS), `webauthn.dll` (Windows, ported from the spike) and a fake for tests. The unlocker tries FIDO2 slots in a fourth, last pass; enrolment, `tswap slots`, guided `init`, `yubikey setup --replace` and the broker learn the new kind.

**Tech Stack:** C# / .NET 10 NativeAOT, `Yubico.YubiKey` 1.18.1 (`Fido2Session`), `webauthn.dll` by `LibraryImport`, xUnit (TswapTests), GitHub Actions on three OSes.

**Spec:** `docs/superpowers/specs/2026-11-06-fido2-slot-design.md` (approved 2026-11-06; it wins where it differs from its base, `docs/superpowers/specs/2026-11-04-yubikey-sdk-portable-design.md`, section "Stage 2 (part B)"). Spike code for reference: branch `design/yubikey-sdk` at `1e3d56b`, `spikes/yubikey-sdk/`: `Fido2.cs` (SDK make-credential, UV assertion through `Fido2Session.GetAssertions`, PIN key collector that never retries), `Fido2Windows.cs` + `WebAuthnNative.cs` (make-credential with direct attestation, UV assertions; struct layouts checked field by field by GLM and MiMo against `webauthn.h` ef82c15), `AuthenticatorDataInfo.cs` (flags, AAGUID, credential id), `Prf.cs` + its tests (the PRF transform and a known vector), and their tests.

## Global Constraints

- Every FIDO2 enrolment and unlock asks for the key's FIDO2 PIN and a touch (user verification required), on every OS. No PIN-free mode.
- Relying-party id: exactly `tswap.crawford.dev` (owner decision 4), for every credential.
- The salt sent to the key is the PRF transform of the slot's 32-byte input, `SHA-256("WebAuthn PRF" || 0x00 || input)`, on every path: the SDK path applies it; on Windows `webauthn.dll` applies it to the PRF input (`dwFlags = 0`, no raw salt flag). The blob records PRF transform version 1.
- Credentials are non-discoverable (`rk = false`, `bRequireResidentKey = 0`, `bPreferResidentKey = 0`): nothing is stored on the key.
- tswap never retries a wrong PIN by itself, never resets a key, never changes an existing PIN. Setting a PIN on a key that has none is the one PIN write, at enrolment, after the user confirms.
- Only Yubico keys: enrolment refuses a key whose AAGUID is not in Yubico's published list (`YubicoAaguids`), naming #193. On Windows enrolment asks for direct attestation (attestation "none" zeroes the AAGUID there; owner run 2026-11-06).
- PIN at the terminal only (Linux, macOS: masked; Windows: its own dialog). No terminal (stdin redirected): FIDO2 slots are skipped at unlock and refused at enrolment, on every OS, Windows included.
- Format compatibility: the blob uses magic `TSYK` version 3, and `init --fido2` writes `Backend = YubiKey`, so v0.2.x answers "needs a newer tswap" for the slot and never misreads it. OTP blobs (v1, v2) and every existing vault are unchanged.
- KEK labels: `tswap/fido2-slot/v1` (no password) and `tswap/fido2-slot/v2` (with the vault password), HKDF-SHA256, 32 bytes, slot id appended to `info`, like `YubiKeySlotKek`.
- NativeAOT publish has zero IL2xxx/IL3xxx warnings on all three OSes.
- `Yubico.YubiKey` stays `[1.18.1]`; no new package.
- British English in new text; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, no session links; commit with explicit paths.
- AGENTS.md is changed only with the owner's approval (Task 9 asks).
- Hardware rule: no automated test creates a credential or asks for a PIN on a real key. Real-key checks are the owner's (Task 9 runbook). The owner's daily key is safe for them (non-discoverable credentials); destructive checks (no-PIN key, wrong-PIN counts, a FIDO2 reset) wait for a spare key.

## Review Focus

1. **A wrong PIN at unlock:** expected: the message names the key and its remaining tries ("… wrong PIN; 6 tries left before this key's FIDO2 is blocked"), says to re-insert the key after three wrong in a row, tries no further FIDO2 slot in this run, and leaves the other slot kinds' errors in the combined message. Pinned by Task 7's `Unlock_Fido2WrongPin_ShowsRetriesAndStops`.
2. **The FIDO2 slot's key is not plugged in (Linux, macOS) while other slots exist:** expected: no PIN prompt at all, and the error names the missing key ("the FIDO2 slot of YubiKey N: plug it in"). Pinned by Task 7's `Unlock_Fido2KeyAbsent_NoPinPrompt`.
3. **A vault whose only way in is a FIDO2 slot, run without a terminal (an agent, CI, a script):** expected: a refusal that says FIDO2 needs a person at a terminal, no PIN dialog on Windows, exit code as for a missing vault password. Pinned by Task 7's `Unlock_Fido2OnlyNoTerminal_RefusesWithoutDialog`.
4. **v0.2.x (and any OTP-only code path) meeting a FIDO2 slot:** expected: the other slots still open; the FIDO2 slot is reported "needs a newer tswap", never decoded as an OTP slot. Pinned by Task 1's `Fido2Blob_V020ParserSaysNeedsNewer` and Task 2's per-call-site tests.
5. **A key whose FIDO2 application was reset (credential gone):** expected: "this key no longer holds the slot's credential (a FIDO2 reset deletes it); enrol it again with `tswap slot add --fido2`", not a PIN or "wrong key" error. Pinned by Task 3's `Assertion_NoCredential_SaysResetKillsTheSlot` and Task 7's `Unlock_Fido2CredentialGone_NamesReset`.
