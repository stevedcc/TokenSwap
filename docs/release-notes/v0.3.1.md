# tswap v0.3.1

Plain, non-secret **fields** on a secret (a username or a URL next to its password); **`slot enrol --via`**, which
enrols a machine over SSH in one command; a **signed Windows exe**; **build provenance attestations** for every
release file; tswap commands that **wait for a busy YubiKey** instead of failing; short secret values masked
only as whole words, with `run` streaming line by line again; and many Windows and PowerShell output fixes.
The release candidates were checked by hand on Windows, Linux and macOS (see "Checked on real hardware" at the end).

## Before you upgrade

- **Re-install the agent skill.** The prompt text changed (fields, `slot enrol`, `run --env`, patterns for
  `names`, short values, British spelling, ASCII only), so `tswap prompt-hash` changed: run the install
  command again (`tswap prompt > …/SKILL.md`).
- **Upgrade every machine that shares a vault folder.** tswap 0.3.0 keeps the bytes of the new fields but
  merges them per record, not per field, so it can drop a newer field change or bring back a removed field
  until every machine runs 0.3.1 ([security-model.md](../security-model.md)). No record format changed and no
  reindex is needed.
- **Short values are masked less** (below): a value under 8 characters is no longer masked inside a longer word
  or number.

## Fields: non-secret data on a secret

- Every secret can carry plain, visible fields: `username`, `url`, `consumers`, `source`, `kind`, `expires`,
  `rotate` and keys of your own. They are data, not a second kind of secret (#311, #325).
- `tswap field set|unset|show` need no sudo; `field show --json` is the form for agents, `--history` shows each
  field's last changes and who made them. `--field`, `--fields` and `--by` also work on `create`, `ingest`,
  `ingest --rotate`, `add` and `rotate`, in the same write as the value.
- `sudo tswap field adopt NAME FIELD --from SECRET` turns a secret that is really a username into a field and
  deletes the secret.
- A field may not hold any stored secret value (burned ones included); `field set` refuses without naming the
  secret. `{{NAME.FIELD}}` in `run` and `# tswap: NAME.…` markers are refused before unlock: fields are never
  substituted. A field write that sets a value refuses until format 2 records are reindexed.
- `export` carries the current fields (export format 3); older exports still import.

## Enrolling a machine over SSH: `slot enrol --via`

- `tswap slot enrol --via <user@host>` runs the four-step enrolment from the joining machine: request and accept
  here, approve and merge on the vault's machine over SSH (#191, #330).
- It runs interactively by default, so sudo's password, the host's vault password and a touch at the host all
  work; passwordless sudo is no longer needed. `--batch` runs it without a terminal, under `sudo -n` (#334).
- The files travel through a staging folder (`slot stage <id> put|get|clean`), checked by SHA-256
  (`--staged <id> --expect <sha256>`). You compare the approve file's fingerprint on both machines and press
  Enter; the Enter prompt shows nothing and takes only an empty line (#334, #359).
- `--remote-tswap <path>`, `--no-remote-sudo` and `--fresh`; a failed step keeps its files, says what is left
  and names the commands to finish by hand. New `-` forms: `slot approve - -`, `slot merge -` (#330, #331, #337).
- It is for a person, never an agent. Details: [multi-machine.md](../multi-machine.md).

## Other new commands and options

- `sudo tswap slot add --tpm` and `slot add --secure-enclave --with-touch|--no-touch` add this machine's own chip
  to a vault it already opens, without request, approve and accept (#309, #324).
- `tswap vault move <folder> [--yes]` moves this machine's record-vault folder, for example out of the config
  folder before sharing it. No sudo. It copies, verifies and keeps the old folder as `<old>.moved-<timestamp>`
  (#310, #322).
- `tswap run --env NAME={{name}} -- <cmd>` puts a secret in the command's environment instead of its argv,
  which other local users can read on Linux. Names such as `PATH`, `LD_*` and `BASH_ENV` are refused (#71, #326).
- `tswap names <pattern>...` filters with `*` and `?` (whole names, case-insensitive; several patterns are a
  union). Quote the pattern in your shell (#7, #336).

## Short values and `run` output

- `add`, `ingest`, `ingest --rotate`, `create` and `rotate` warn when a new value is shorter than 8 characters.
  The warning names the secret, never the value or its length; nothing is refused (#314, #317).
- `redact` and `run` mask a value under 8 characters only as a whole word (`-` counts as a word character),
  so a short value no longer blanks out ordinary text, JSON or numbers that contain it (#314, #344).
- `run` holds short substituted values back by class, so its output streams line by line again instead of
  waiting for more output (#341, #363).

## Markers and `tocomment`

- A multi-line or control-character value survives a `# tswap:` marker: double-quoted fills escape it, a
  single-quoted fill that needs escaping is rewritten in double quotes, and a `KEY=` line refuses it (#315, #318).
- `tocomment` turns a literal block scalar (`key: |`) holding a stored value into one marker line; `check` warns
  about markers under `data:` in a Kubernetes Secret, which must be base64 (#318).
- `tocomment` leaves a line inside a YAML block scalar alone when it holds an encoded form of a value, and warns
  with the line number and the secret's name: a marker would fill in the plain value (#319, #321).

## Several tswap commands at once

- Two tswap commands that need the YubiKey or security key take turns: the second prints that it is waiting and
  goes on when the first is done, instead of failing or taking its touch (#42, #173, #273, #301, #342).
- It waits 60 seconds at most; Ctrl-C stops it. A broker waits at most 25 seconds on an unlock. The lock is
  `~/.cache/tswap/yubikey.lock` (`%LOCALAPPDATA%\tswap\yubikey.lock` on Windows), per user
  ([setup.md](../setup.md#several-tswap-commands-at-once)).

## Prompts and FIDO2 messages

- Every prompt read at a terminal discards what was typed before it appeared, so a stray YubiKey OTP no longer
  becomes the answer or a wrong PIN. Piped input is never discarded. Type your answer after the prompt (#293, #338).
- After a replug, a FIDO2 device error says to wait a second and run the command again (#289).
- A key with no PIN tries left, or one that needs re-inserting, is refused before the PIN prompt; the touch line
  says the key blinks only if the PIN is right (#290).
- A tried key's failure comes first, the "plug it in" notes for absent keys are gone, and each enrolled key has
  one name everywhere (#291).

## Windows and PowerShell

- `run` hints at the quoted form when PowerShell has eaten the braces of an unquoted token (`{name}`), or passed
  it as `-encodedCommand <Base64>`, which both Windows PowerShell 5.1 and PowerShell 7 do (#348, #356, #376).
- On a Windows console, `run` turns on VT processing and drops the child's window-title sequences, so ConPTY's
  escape sequences no longer print as text (#349, #356).
- While stdout and stderr are consoles, tswap's output is UTF-8: no more `?` glyphs or garbled banners, and a
  secret with non-ASCII characters is redacted on a code-page console (#355, #294).
- Windows messages name an elevated prompt instead of `sudo` (`init --yubikey`, `init --fido2`, the inline-code
  refusal) (#294, #338, #356).
- The agent prompt text is ASCII only, so redirecting it (as the install script does) no longer loses
  characters (#375).

## `slots` and vault files

- `tswap slots` names each hardware slot's kind from the slot's own data, so another machine's TPM or Secure
  Enclave slot is no longer labelled with this machine's kind; "this machine's" appears only on its own row (#350).
- Opening a record vault narrows loose vault files back to 0600/0700, with one notice. Syncthing on Linux or
  macOS applied `0644` to files a Windows machine wrote; multi-machine.md gives the Syncthing settings (#347).
- A vault whose password slots exist but whose `vault-password` file is missing can no longer get a new, first
  one: `slot add --yubikey`, `slot add --fido2` and `recover` refuse and point at `--no-password` (#320, #336).

## Release files

- **Signed Windows exe** (#368, #379): `tswap.exe` is Authenticode-signed with a Certum Open Source code signing
  certificate ("Open Source Developer Steven Crawford") and an RFC 3161 timestamp, which Smart App Control
  accepts. Check it in PowerShell with `Get-AuthenticodeSignature .\tswap.exe` (`Status` is `Valid`).
- **Build provenance attestations** (#371, #372): every release file is attested by the release workflow.
  Check a download with `gh attestation verify <file> --repo stevedcc/TokenSwap`
  ([install.md](../install.md#check-a-download)).
- **Ubuntu 26.04** (sudo-rs, Rust coreutils) runs in CI next to 24.04. The test failures there were in the tests,
  not in tswap; the release's Linux build stays on 24.04 (#339, #358).

## Small changes

- British spelling throughout: the command is `slot enrol` (`enroll` still works), and messages and docs say
  enrol, enrolment, behaviour. No flag, file name or environment variable changed (#254, #352, #353, #364).
- Needs RedactingPty 1.2.0 (for `run --env`).

## Known issues

- `yubikey setup --replace`, when the key's own FIDO2 slot is the only other way in, still fails as in 0.3.0
  (#302): nothing is written; give the vault another way in first.
- In PowerShell, an unquoted `{{@values.yaml}}` doesn't parse at all; quote every token
  ([install.md](../install.md#windows-notes)).
