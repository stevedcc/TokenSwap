# tswap v0.2.0

A breaking release: classic vaults are migration-only, records gain format 3 with keyed
fingerprints, and `init` makes record vaults.

## First: convert a classic vault

```bash
sudo tswap migrate --to-records
```

On a classic single-file vault (`secrets.json.enc`) every command now refuses with that hint,
except `migrate --to-records` (and the plain `migrate` touch-upgrade guide) and `export`, so you
can always take your secrets out. A two-YubiKey XOR vault becomes a keyring vault in the same run:
plug in every enrolled YubiKey (each gets its own slot) and store the recovery key it prints once.
A single-slot TPM / Secure Enclave vault from before keyring vaults can't be converted: export it,
create a new vault in another config folder and import.

## Then: `sudo tswap vault reindex`

Record format 3 splits each record into an encrypted metadata section (name, burns, the version
list and keyed fingerprints of every retained value) and one value section per retained value,
encrypted once and copied byte for byte by later writes. Commands that need only names, burns or
fingerprints no longer decrypt values; the next releases build `redact`, `tocomment`, `run` and
`extract` on this.

`sudo tswap vault reindex` rewrites every record that isn't current in format 3 (each with a new
write stamp, so it merges like any other write), refuses before writing anything if a record can't
be read, prints counts only, and writes the `record-format` marker into the vault folder last. From
then on every machine sharing the folder writes format 3; before that, a vault keeps writing
format 2. Running it again rewrites nothing; an interrupted run is finished by running it again.
`vault merge` copies the marker from a reindexed copy. New vaults (`init`, `migrate --to-records`)
start in format 3.

## Mixed fleets

**Machines still on 0.1 refuse reindexed records until they are upgraded.** They never delete or
overwrite a record written in a newer format: this was verified against the 0.1 code path before
the codec changed (brief T16-S1 task 3: create, burn, delete, `vault merge`, rotate, import and
migrate all left a newer-format record byte-identical and reported it unreadable). So upgrading
every machine before `vault reindex` is recommended, not required: until a machine is upgraded it
can't read the reindexed secrets, and anything it writes in format 2 after the reindex is reported
as "not fingerprinted" until a 0.2 machine writes that record, merges or reindexes again. A copy
kept in step with `vault merge` doesn't need its own reindex: in a folder that writes format 3, a
merge rewrites every record it can read whose file isn't format 3 yet, even one equal on both sides
(a record it can't read, such as one written by a newer tswap, is never touched).

## `init` makes a record vault

- Plain `tswap init` now does what `init --keyring` did (one YubiKey slot plus a recovery slot),
  in the record store at `<config dir>/vault`, marked for format 3; `--tpm` and `--secure-enclave`
  likewise. `--keyring` is still accepted and changes nothing.
- New: `tswap init --folder <dir>` creates the vault folder at `<dir>` (absent or empty), for
  example a Syncthing or cloud-drive folder.
- The two-YubiKey XOR vault can no longer be created; add a second key with
  `sudo tswap slot add --yubikey`.
- `init` on a config folder holding a classic vault refuses: convert it with
  `sudo tswap migrate --to-records`, or move `config.json` and `secrets.json.enc` aside.

## Merging copies: same version stamp, different values now fails closed

Copies of a record are now merged all at once, and the result doesn't depend on their order. Two
copies that hold **different values under one version stamp** (only damage or a clock rollback can
produce them) used to be resolved by a content tie-break (a tombstone won over a value, then the
larger value bytewise). They are now a **conflict**: that record becomes unreadable, `get` and
`run` of it fail, nothing overwrites it, and the warning names the record; remove the damaged
conflicted copy to make it readable again. The tombstone-wins tie is gone too. Two copies of one
value with different ciphertexts (two machines that each converted it) are legitimate and converge
on one of them.

## Also

- `vault reindex` is a sudo command (it decrypts every value once).
- A plain `slot accept` (without `--vault-dir`) on a machine without a vault now creates a record
  vault at `<config dir>/vault` with the `record-format` marker, as `init` does (it used to write a
  classic single-file vault). The new vault holds the keyring and no secrets: bring them in with
  `sudo tswap vault merge <a copy of the other machine's vault folder>`, or join a shared folder with
  `slot accept ... --vault-dir <folder>` or `init --vault-dir <folder>` instead.
