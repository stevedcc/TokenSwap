# tswap v0.3.2

A security release. On Windows, `tswap run` could pass a secret to a batch file (`.cmd`, `.bat`) in a way `cmd.exe`
parses again, so a value with the right characters ran a command (advisory GHSA-j65j-m4j2-89g2). This release refuses
that, closes several ways around `run`'s inline-code check, stores piped non-ASCII secrets correctly on Windows, and
masks values that look like secrets the vault doesn't know in `redact`.

## Before you upgrade

- **On Windows, re-ingest any secret with non-ASCII characters that you piped into `tswap ingest`** (or
  `ingest --rotate`) with an earlier version: piped input was decoded with the console code page, so `café` was stored
  as a different value. Secrets typed into `add` or generated by `create`/`rotate` are not affected.
- **Re-install the agent skill.** The prompt text changed (how a script reads a secret, on every OS, and never a batch
  file or `cmd`), so `tswap prompt-hash` changed: run the install command again (`tswap prompt > …/SKILL.md`).
- **Some `run` commands that used to work are now refused** (below). Each refusal says how to do it instead.

## Security: batch files on Windows (GHSA-j65j-m4j2-89g2)

- On Windows, `run` refuses when a substituted value contains a character `cmd.exe` interprets (`" & | < > ^ % ! ( )`,
  CR or LF) and any word of the command is a batch file (`.cmd`, `.bat`, in any spelling Windows accepts) or `cmd`
  itself; the same for a `{{@file}}` copy whose name or temporary folder holds such a character. The refusal names the
  secrets, never their values (#392, T47).
- The ways that work, proven on Windows CI with a corpus of hostile values: a PowerShell script
  (`run powershell -File .\deploy.ps1 '{{secret}}'`, read as `$args[0]`), or the environment
  (`run --env PW={{secret}} deploy.cmd`, read with `setlocal EnableDelayedExpansion` and `!PW!`). New guide:
  [Passing secrets to scripts](../scripts.md), with bash, zsh, PowerShell and Git Bash on Windows.

## Security: `run`'s inline-code check

`run` refuses interpreters given inline code, because inline code can transform and print a secret past redaction.
Up to 0.3.1 the PowerShell part of that check missed spellings PowerShell accepts. Now:
- PowerShell's parameters are recognised by PowerShell's own rule: `-`, `--`, `/`, the Unicode dashes, surrounding
  spaces, any prefix (`-c`, `-co`, `/command`, `--encodedcommand`, `–c`).
- The program word is read as Windows reads it (`pwsh.exe.`, `pwsh.exe::$DATA`).
- `powershell` (Windows PowerShell 5.1) is refused unless `-File` comes first: 5.1 runs a plain first argument as code
  (#401).
- PowerShell or `cmd` reading code from stdin is refused: a bare `powershell`, `pwsh` or `cmd`, `-File -`,
  `pwsh /dev/stdin`, `-NoExit`, and `deno run -`.
- An image whose name is an interpreter (`docker run python:3.12 -c …`, a digest too) is checked as that interpreter;
  `wsl` is a wrapper (`wsl bash -c …` is refused, a bare `wsl` too).
This check is a guard against an agent running its own code, not a sandbox: a program tswap doesn't know can still
run code ([security model](../security-model.md) lists what it doesn't catch).

## Piped input is UTF-8 on every OS

- `ingest` and every other command that reads piped text read it as strict UTF-8 on Windows, Linux and macOS. A
  leading UTF-8 byte order mark is ignored; a UTF-16 or UTF-32 one switches to that encoding. Input that isn't valid is
  refused and nothing is stored (on Linux and macOS invalid bytes used to be stored as `�`).
- Windows PowerShell 5.1 pipes text to programs as ASCII by default (`é` arrives as `?`, which tswap can't detect): set
  `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)` first, or use PowerShell 7.

## redact

- `redact` masks a value that looks like a credential it doesn't know (a keyword such as `password`, `token`, `secret`
  or `key`, then 12 or more characters) as `[POSSIBLE SECRET]`, and its warning names the line and the keyword, never
  the value (#389).

## Known issues (0.3.3)

- Git Bash on Windows changes some ASCII values passed as arguments (`'`, braces, globs, line breaks): use
  `--env` with `"$PW"` there (#402).
- `get` on Windows prints non-ASCII values in the console code page when its output is piped (#403).
- `redact` doesn't mask a stored value containing CRLF (#398); `tocomment` doesn't find a value with a line break
  inside (#399); Unicode normalisation across machines (#400).
- More `run` guard gaps found in review, filed for 0.3.3: #404, #405, #406, #407.
